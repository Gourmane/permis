# طريقي — التدريب على قانون السير المغربي

تطبيق عربي بالكامل، مخصص للهاتف والحاسوب. يعرض صور الأسئلة من فيديوهاتك، يدعم عدة إجابات صحيحة، ويحفظ تقدمك في المتصفح عبر IndexedDB. نسخة الإنتاج ثابتة: لا حسابات، ولا قاعدة بيانات، ولا API، ولا ذكاء اصطناعي، ولا معالجة فيديو وقت الاستخدام.

## المحتوى الحالي

14 فيديو، 14 سلسلة، 420 سؤالًا. 380 سؤالًا بإجابات تم التحقق منها بصريًا. السلسلة الأولى تحتوي 40 سؤالًا لم تظهر إجاباتها بصريًا؛ هذه الأسئلة معلّمة `needsReview: true` ومستبعدة من التدريب. لا توجد إجابات أو تفسيرات مخترعة. إجابات الفيديو قد تحتاج مراجعة وفق مواد تدريبك المعتمدة.

قبل النشر راجع:

- `reports/extraction-report.md`: التقرير والحدود والمشكلات والأسئلة غير المؤكدة.
- `reports/verified-extraction.json`: الإجابات المقروءة من إطارات التصحيح وبصمات مصادرها.
- `src/data/questions.generated.json`: بيانات الأسئلة النهائية.
- `src/data/series.generated.json`: تعريف السلاسل.
- `public/questions/`: الصور المحسّنة.
- `/review/`: صفحة مراجعة المحتوى؛ غير مرتبطة بقائمة المتعلم، لكنها ليست صفحة محمية أو سرية.

## التشغيل المحلي

يلزم Node.js 22 أو أحدث وnpm. من مجلد المشروع:

```powershell
npm ci
npm run dev
```

افتح `http://localhost:3000`. للتحقق وبناء نسخة الإنتاج:

```powershell
npm run lint
npm run validate-content
npm test
npm run build
npm start
```

`npm start` يعرض الملفات الثابتة من `out` محليًا. لا تحتاج نسخة الإنتاج إلى خادم التطبيق هذا؛ يمكن لأي استضافة ثابتة تقديم `out`. البناء ينتج صفحات HTML وصورًا وشيفرة للمتصفح فقط. ملفات Python والفيديوهات غير مطلوبة للبناء.

## بنية المشروع

- `src/app/`: الرئيسية، السلاسل، الاختبار، الأخطاء، المواضيع، التدريب المختلط، المحفوظات، الإحصائيات، الإعدادات، المراجعة.
- `src/components/`: القوائم والحوارات والعناصر المشتركة.
- `src/features/`: لوحة الدراسة والاختبار وقوائم الأسئلة.
- `src/lib/logic.ts`: مقارنة الإجابات، التقييم، تاريخ الأخطاء، الاختيار الموزون والتحقق من النسخ.
- `src/lib/download.ts`: إنشاء تصحيحات PNG وZIP داخل المتصفح.
- `src/storage/`: طبقة IndexedDB وحفظ الحالة بالتتابع لتفادي تضارب الكتابات.
- `src/types/`: أنواع TypeScript.
- `src/data/`: بيانات الإنتاج الثابتة.
- `public/questions/`: صور WebP.
- `scripts/`: أدوات استخراج وتحقيق ومعاينة؛ أدوات الفيديو للتطوير فقط.
- `reports/`: تقرير الاستخراج وأدلة الاختبارات.
- `tests/`: اختبارات منطق مستقلة.

## استخراج الفيديوهات

المصادر داخل `source-videos`، ويمكن وضعها في مجلدات فرعية. تُفحص صيغ MP4 وMOV وWEBM وMKV. الملفات العربية الحالية تتضمن رقم السلسلة، فجرى ترتيبها عدديًا بحسب ذلك الرقم؛ تستخدم الأسماء الأخرى ترتيبًا طبيعيًا. يخزن التقرير مسار المصدر النسبي.

لإعادة الاستخراج باستخدام Python 3٫12 أو أحدث:

```powershell
python -m pip install --target .tools/python -r scripts/requirements.txt
npm run extract-content
```

العملية تشغّل:

1. `scan-videos.py`: جرد المصادر وإنشاء معاينات.
2. `detect-scenes.py`: أخذ عينات كل ثانيتين وكشف تغيّر الشرائح؛ تستخدم الفيديوهات الحالية مقدمة تبدأ بعدها الأسئلة قرب الثانية 42 في الأول والثانية 24 في البقية.
3. `generate-content.py`: دمج تغيّرات الحجم لنفس السؤال، إنشاء صور WebP بجودة 94، وربطها بالقرارات البصرية المعتمدة.
4. `write-report.py`: إنشاء التقرير وبصمات المصادر ومرشحات التشابه.

الاستخراج ليس تخمينًا آليًا للإجابات: قرارات الإجابات الحالية قُرئت من صور التصحيح لكل سلسلة ووُثّقت في `reports/verified-extraction.json`. لا يعتمد الإنتاج على أدوات قراءة الأرقام التجريبية. لا تُستخدم تلك القرارات إذا تغيرت بصمة فيديو المصدر؛ تتوقف العملية حتى تعاد مراجعته. عند إضافة فيديو جديد يجب مراجعة الشرائح والتوقيت وقرارات الدمج وعدد الأسئلة قبل الاعتماد. ملفات الأدلة في `reports/frames` و`reports/contact-sheets` محلية ومستبعدة من Git.

التوقيت المسجل هو **توقيت الإطار المستخرج**: إطار السؤال قبل كشف الإجابة، وإطار التصحيح قرب نهاية العرض. ليس ادعاء بدقة بداية ظهور السؤال أو بداية كشف الإجابة. الثقة تقييم نوعي. الأسئلة التي لا تظهر إجاباتها تبقى للمراجعة، ولا تدخل في التدريب.

أزيل عمود تحكم المحاكي الذي يتضمن نصوصًا فرنسية. الصورة الأصلية وعلامات الطريق والعلامات المائية محفوظة كمصدر السؤال؛ لم يُختلق نص بديل. الواجهة والأخطاء والإعدادات والتصحيحات بالعربية فقط.

`source-videos` مستبعد من Git لأن الفيديوهات كبيرة وغير مطلوبة للنشر. ملف `.gitignore` يستبعد أيضًا أدوات الاستخراج واللقطات المحلية ونسخ البناء. لا تضع أسرارًا أو فيديوهات في `public`.

## تعديل إجابة أو موضوع

من `/review/` أو التقرير، ابحث عن معرف مثل `s02-q001`. شاهد الفيديو عند توقيتي السؤال والتصحيح، وتحقق من **كل** الأرقام المحددة. عدّل `correctAnswers` كقائمة، مثل `[1, 3]`، و`topic` من التصنيفات في `src/lib/content.ts`. إذا لم تتأكد، أبقِ `needsReview: true`.

للتصحيح الدائم عدّل أيضًا إدخال السؤال المقابل في `reports/verified-extraction.json`، وإلا ستعيد عملية الاستخراج القرارات القديمة. بعد التحقق من إجابات السلسلة الأولى أضف إجاباتها ومواضيعها ووقت إطار التصحيح الموثق ثم أعد التوليد؛ لا تحول `needsReview` إلى false قبل ذلك. شغّل `npm run validate-content` ثم `npm run build`.

## التقدم والنسخ الاحتياطي

قاعدة IndexedDB باسم `tariqi-progress` وإصدار مخطط 1. تحفظ سجلًا واحدًا لكل سؤال: المحاولات الصحيحة والخاطئة، آخر إجابة، آخر خطأ وتاريخه، التحسن، والحفظ. تحفظ أيضًا جلسة التدريب الحالية ونتائج السلاسل والإعدادات. اكتمال السلاسل والإحصائيات مشتقان من النتائج والسجلات. الإجابة الصحيحة لاحقًا لا تمحو تاريخ الأخطاء.

التقدم يخص **هذا المتصفح على هذا الجهاز فقط**. لا مزامنة تلقائية. حذف بيانات المتصفح قد يمحو التقدم. انقله من الإعدادات: صدّر JSON من الجهاز الأول ثم استورده في الثاني. يُتحقق من إصدار النسخة ومعرفات الأسئلة والإجابات والإحصائيات والنتائج والجلسة قبل أي كتابة. الاستيراد يستبدل التقدم الحالي بعد تأكيد، والحذف يحتاج تأكيدًا أيضًا.

## الاختبار وتجربة الهاتف

`npm test` يشغّل 16 اختبارًا لمنطق الإجابات المتعددة، النتائج، حفظ الأخطاء، سلامة الاستيراد، معرّفات الأسئلة، تهيئة كل سلسلة متاحة، والأرقام اللاتينية. `npm run test:browser` يتحقق من السلاسل 2–14 والتصحيح والحفظ والنسخ الاحتياطي في متصفح معزول. `npm run test:quiz` يكمل سلسلة من 40 سؤالًا ويتحقق من النتيجة والتدريب حسب المحور والتدريب المختلط والأخطاء. تشمل المقاسات 360×800، 375×812، 390×844، 412×915، 430×932، 768×1024، 1366×768، 1440×900، 1920×1080. التقارير في `reports/browser-test-report.json` و`reports/quiz-test-report.json`.

زر التكبير يفتح حوارًا يدعم التكبير الإضافي والعرض الكامل إن دعمه المتصفح. أزرار 1–4 ثابتة كما في محاكي الامتحان؛ اختر الأرقام الموجودة في نص السؤال. مفاتيح 1–4 تحدد الإجابات، ومفتاح الإدخال يؤكد أو ينتقل. لا يتدخل الاختصار داخل حوار أو حقل إدخال.

يوجد manifest وأيقونات لتجربة مستقلة عند الإضافة للشاشة الرئيسية. التصفح العادي هو الأساس، وتحميل الصفحات والصور يحتاج اتصالًا؛ لا يوجد ادعاء بعمل كامل دون إنترنت.

فحص اعتماديات الإنتاج لم يسجل ثغرات. فحص أدوات التطوير سجّل تنبيهًا في سلسلة `eslint-config-next` إلى `braces` بدون إصلاح متوافق منشور وقت التنفيذ؛ لا تدخل هذه الأدوات في الملفات الثابتة المنشورة. لا تستخدم `npm audit fix --force` لأنه يقترح إصدارًا أقدم من Next.js.

## النشر على GitHub وVercel

تم تهيئة مستودع Git محلي على الفرع main. أنشئ مستودعًا فارغًا على GitHub. من هذا المجلد، بعد مراجعة المحتوى:

```powershell
git init
git add .
git commit -m "إضافة تطبيق طريقي"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

استبدل اسم المستخدم والمستودع بعنوانك الحقيقي. تحقق أن `source-videos` و`.tools` ونسخ التقدم الشخصية غير مضافة.

في Vercel اختر **Add New → Project** واستورد المستودع، واختر Next.js. مجلد المشروع هو الجذر، أمر البناء `npm run build`، واترك إعدادات الإخراج الافتراضية لإطار Next.js. لا تضف متغيرات أسرار؛ لا يحتاج المشروع إليها. اضغط Deploy. يعتمد المشروع `output: 'export'` ويولّد `out` كما تشرح [وثائق Next.js للتصدير الثابت](https://nextjs.org/docs/app/guides/static-exports)، وتشرح [وثائق Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs) استيراد مشروع Next.js.

بعد النشر افتح الرابط على Android، جرّب سؤالًا وتصدير التقدم، ثم استخدم خيار الإضافة إلى الشاشة الرئيسية من المتصفح إذا رغبت.

لتشغيل اختبار المتصفح محليًا، أبقِ `npm start` في نافذة، وشغّل `npm run test:browser` في نافذة ثانية. يستخدم Chrome المثبت افتراضيًا. أو ثبّت Chromium عبر `npx playwright install chromium` واضبط `$env:PLAYWRIGHT_BROWSER_CHANNEL='chromium'` قبل تشغيل الاختبار. هذا اختبار تطوير فقط، وليس اعتمادًا في التطبيق المنشور.


## تحديث الواجهة والأرقام

واجهة عربية RTL بخلفية زرقاء داكنة ونمط تشوير أصلي خفيف. البطاقات كبيرة، والمفاتيح الأربعة تقبل الاختيار المتعدد قبل التأكيد. على الحاسوب تظهر الصورة والإجابات يسارًا والتقدم والتنقل يمينًا، وعلى الهاتف يصبح التدريب عمودًا واحدًا. التصحيح لا ينتقل تلقائيًا.

كل الأرقام في الواجهة لاتينية. `src/lib/numbers.ts` يستخدم `ar-MA-u-nu-latn`، وتُعزل النسب مثل 1/40 والإجابات مثل 1 + 3 عبر `Numeric`. تُحوّل تسميات النسخ القديمة دون تغيير معرّفات الأسئلة أو سجل التقدم.

## سبب توقف السلسلة 1

المعرّف `series-01` ومسارات الصور ومعرّفات الأسئلة صحيحة. كل الأسئلة الأربعين تحتوي `correctAnswers: []` و`needsReview: true`؛ لذا كانت تصفية الأسئلة القابلة للتصحيح تعطي قائمة فارغة. لا يوجد مفتاح إجابات موثوق في المصدر المستخرج. رابط السلسلة الآن يفتح مراجعة محتواها مع توضيح السبب. يلزم التحقق من شرح فيديو المصدر وتوثيق جميع الإجابات قبل فتح التدريب المصحح.

`npm run validate-content` ينشئ `reports/content-integrity.json` ويبلغ عن أي سلسلة لا تحتوي على أسئلة قابلة للتصحيح. `npm run validate-content:strict` يفشل عند وجود هذه الحالة؛ يُتوقع أن يفشل حاليًا بسبب السلسلة 1. فحص البناء يسمح بإبقاء المحتوى المعزول ضمن التطبيق، ويظل المنع ظاهرًا بدل حذف الأسئلة أو تخمين إجاباتها.

## التصدير الثابت على Windows

كشف اختبار المتصفح أن Next.js 16.4 يكتب بعض ملفات route payload في مجلدات على Windows، بينما يطلب المتصفح أسماء مفصولة بالنقاط. خطوة postbuild في scripts/normalize-export.mjs تطبع الأسماء المطابقة لبروتوكول المتصفح في out، وتحفظ الملفات الأصلية وتمنع استبدال ملف بمحتوى مختلف. هذه الخطوة تعمل تلقائيًا مع npm run build، بما في ذلك قبل نشر مجلد out على أي استضافة ثابتة.
